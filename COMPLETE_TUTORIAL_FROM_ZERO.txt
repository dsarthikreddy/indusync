1. THE GOLDEN RULES
=====================================================================================================
 1. The DOOR IS THE BOSS. The ESP32 decides who enters, even with no internet and no laptop. Every cloud
    service is an extra on top. If a cloud service fails, the door still works.
 2. Change ONE thing at a time, then test. Never fix three things at once.
 3. NEVER type these in the Serial Monitor while testing (they delete things):
        clear        (deletes ALL saved faces)
        forget <name> (deletes one person's face)
        resetphones  (deletes all phone keys)
        clearpasses  (forgets used visitor passes)
    Safe commands: help, list, report, sensors, cloud, events, log, stats, wifi, phones, visitors.
 4. On the websites, "Start new day" / "reset" clears TODAY's attendance (faces stay). Use it only when
    you really want a new day.
 5. Keys are secret. Never send them to anyone or paste them in chat/screenshots. Secret files:
        tools\stage3_state.json    tools\sheet_settings_code.txt    5_n8n\n8n.env    secrets.h
 6. Before big changes: make a backup (chapter 18). It takes 2 minutes.
 7. If something looks broken: do NOT press random buttons. Find the symptom in chapter 19.
 8. Wi-Fi must be 2.4 GHz (the ESP32 cannot use 5 GHz). Phone hotspot: switch on "Maximise compatibility".

 WHAT WORKS WITHOUT THE LAPTOP (laptop OFF, board powered and on Wi-Fi):
   YES: door control (card + face, QR passes, phone key), attendance saved on the board,
        24/7 website (Firebase), Control buttons from anywhere, sensors on the website,
        ThingSpeak graphs, Blynk panel, Telegram alarms and /status /open,
        Google Sheet log, daily 8 PM report by email/Telegram/WhatsApp, WhatsApp arrival notices.
 REQUIRES THE LAPTOP:
        CCTV camera and AI recognition, photos of unknown people, the cross-check (door vs CCTV),
        the local website (localhost:8000), n8n (weekly/monthly reports + watchdog; it catches up later).
 WORKS WITHOUT INTERNET (board powered, router off): the door itself, attendance on the board, all
        board commands in Serial Monitor. Events wait inside the board and upload automatically when
        the internet comes back (nothing is lost).
 WORKS WITHOUT WI-FI AT ALL: type  wifi off  -> the door behaves exactly like the old v6.
 BOARD POWER OFF: nothing works (no door control). Cloud shows "door offline".

5. THE ESP32 DOOR BOARD
=====================================================================================================
5.1 INSTALL ARDUINO IDE AND THE BOARD PACKAGE (once; skip what you already did for v8.1)
  1. Open Arduino IDE. Left bar: Boards Manager (chip icon) > search  esp32  > "esp32 by Espressif Systems"
     > choose version  2.0.17  in the small drop-down (NOT 3.x) > Install. Wait until "INSTALLED".
     If a newer version is installed: choose 2.0.17 again and install over it.
  2. Library Manager (books icon). Install: "Adafruit GFX Library", "Adafruit SSD1306", "MFRC522" (by
     GithubCommunity). Click "Install all" if it offers dependencies.  (BLE, Wi-Fi, Preferences and the
     face-AI come with the board package; the QR reader is inside the sketch folder.)
5.2 OPEN THE FIRMWARE
  File > Open > C:\SARTHIK_Room\1_Door_Board_v8_2\classync_stage1_v8_2\classync_stage1_v8_2.ino
  The folder also holds secrets.h, quirc.h, quirc_lib.c and partitions.csv - keep them together.
5.3 SETTINGS (Tools menu)
  Board: ESP32S3 Dev Module        PSRAM: OPI PSRAM        Flash Size: 16MB
  Partition Scheme: leave as you used for v8.1 (the partitions.csv in the sketch folder is used)
  Port: the COM port of the board.   Board package must say 2.0.17.
5.4 CONNECT AND UPLOAD
  1. Plug the USB cable into the board's USB port that worked for your earlier uploads (the board has two:
     "USB-UART" and "USB-OTG" printed on its back). Windows makes a COM port. Tools > Port > choose it.
  2. Click the right-arrow Upload button. First compile takes 3-6 minutes. Wait for "Done uploading".
  3. If "Failed to connect": hold the BOOT button, tap EN/RST, release BOOT, press Upload again.
  4. Tools > Serial Monitor. Bottom right: speed 115200 and "Newline". Press the EN/RST button once.
5.5 WHAT THE SERIAL MONITOR SHOWS AT START (similar text; the order is the same)
   ===== CLASSYNC 4.0 v8.2: RFID + FACE + QR + PHONE KEY + WEBSITE + CLOUD + 15 SENSOR SLOTS =====
   OLED OK
   Camera OK, sensor PID 0x2145
   Faces loaded from permanent memory: N of 3 students
   RC522 version 0x92 -> OK            (0x91 or 0x92 is normal)
   Wi-Fi: connecting to "ACT" in the background ...      then   Clock set from the internet.
   Cloud: Firebase off, ThingSpeak off, Blynk off, Telegram off. Sensors on: chip_temp occupancy wifi_signal free_memory
 (After the cloud is set up the Cloud line says ON for the services you configured.)
  Errors here -> Fix:
   "OLED NOT FOUND"                    -> check OLED wires VCC/GND/SDA=41/SCL=42.
   "Camera init FAILED" / CAM ERROR    -> switch off, re-seat the camera ribbon (lift the latch, push in, close).
   "PSRAM not found"                   -> Tools > PSRAM > OPI PSRAM, upload again.
   "RC522 ... NOT FOUND"               -> check the 7 RFID wires and 3.3V (not 5V).
   Garbage letters                     -> Serial Monitor speed must be 115200.
5.6 BASELINE TEST OF THE DOOR (do this BEFORE the cloud; it proves nothing old was damaged)
   1. Serial: type  list  -> your students with "face saved" (or "NO FACE YET").
   2. Tap a registered card, look at the camera 30-50 cm away in good light.
      Expected: OLED CHECKING -> PRESENT; both LEDs on, two chirps, servo opens ~3 s, then locks.
      Serial: "ATTENDANCE MARKED: <name>".  (First time ever for a card: it enrols 3 photos instead.)
   3. Tap an UNKNOWN 13.56 MHz card (college ID, metro card): red LED blinks + loud alarm; OLED DENIED.
   4. Type  report  -> shows PRESENT / ABSENT. Type  events  -> list of events.
   5. Phone key and QR pass: test as you did before (phone near the door; pass image from
      6_Visitor_Pass_Maker\make_pass.py shown to the camera).
   6. New card for Rozy: type  learncard rozy , tap her card within 60 s, look at the camera.
   Do NOT type clear / forget / resetphones / clearpasses.
5.7 CLOUD STATUS ON THE BOARD
   Type  cloud  (after setup, upload done, wait 1-2 minutes). Expected, similar to:
      ---- Cloud links (keys in secrets.h; empty key = off) ----
        firebase   ON   ok 5      failed 0     working
        thingspeak ON   ok 3      failed 0     working
        blynk      ON   ok 1      failed 0     working
        telegram   ON   ok 2      failed 0     working
        events waiting for Firebase: 0
   A service you did not set up shows "off" (normal). A problem shows words after "failed", e.g.
      "device login refused (check email/password)"  -> secrets.h FB_DEVICE_EMAIL / FB_DEVICE_PASS wrong.
          Fix: run Setup Stage 3.bat again (delete  "files": true,  in tools\stage3_state.json first),
          then upload again.
      "not allowed (rules / members list)"  -> the door board's e-mail is not in Members as "Door board".
          Fix: Firebase console > Firestore > Data > members > add document named
          door-1.board@sarthik.room with fields role=device (string), name=door board (string).
      "bad bot token" / "chat not found (send /start)"  -> chapter 12.
      "bad token" (Blynk) -> chapter 9.     "too fast or bad key" (ThingSpeak) -> chapter 8.
   Type  sensors  -> 15 slots. Expected: S01 chip_temp ok ~40, S02 occupancy ok 0.., S03 wifi_signal ok -50,
      S04 free_memory ok; the rest "off". A sensor you enabled but did not wire shows "no_data" (check wires).
5.8 CHANGING WI-FI
   Edit secrets.h: NET1_SSID / NET1_PASS (main) and NET2_SSID / NET2_PASS (backup, e.g. your phone hotspot).
   Keep the quotes. Upload again. Type  wifi  -> shows the board address (like http://192.168.1.50) and the door key.
5.9 ADDING SENSORS LATER: see SENSORS_GUIDE.txt. Enable one at a time, upload, type  sensors , check.

   Graph looks flat/odd                             -> a sensor shows fault/no_data on the board (wiring/scale).

9. BLYNK  (small phone panel)
=====================================================================================================
 SET UP: STAGE3_SETUP_GUIDE.txt step 5 (template, 5 virtual pins, device, token). The token went into secrets.h.
 DATA PINS: V0 online(1), V1 present today, V2 temperature, V3 open alerts, V10 "Open door" button.
 OPEN: https://blynk.cloud > Devices > click your device > tabs: Dashboard (widgets), Timeline, Device Info.
       Phone: Blynk IoT app > the device.
 HOW OFTEN: the board updates Blynk every 3 minutes (free-plan limit). The numbers are therefore up to 3 min old.
 IMPORTANT, HONEST NOTE: the board talks to Blynk with short web requests, not a permanent connection. So Blynk may
   show the device as "Offline" even though values update. That is expected. If the Switch widget looks greyed out
   while "Offline", press the button through this link instead (replace TOKEN with your 32-letter token):
        https://blynk.cloud/external/api/update?token=TOKEN&V10=1
   Open it in a browser. I could not test Blynk's live app here, so please verify it on your phone (below).
 TEST (safe):
   1. Wait up to 3 min. Dashboard shows V1 = present count, V2 = temperature, V3 = alerts.       [Blynk dashboard]
   2. Open-door test: set V10 to 1 (switch or the link above) -> within 3 minutes the door opens ONCE and V10 goes back
      to 0. Serial Monitor prints ">>> BLYNK: open door button".                                  [Serial + door]
 COMMON ERRORS -> FIX:
   Board  cloud  says blynk "bad token"      -> token wrong. Blynk > Devices > device > Device Info > copy token again;
                                                run Setup (delete "blynk": ... line in stage3_state.json) and upload.
   Values never change                       -> template datastreams missing (V0,V1,V2,V3,V10 must exist, exact numbers).
   Door opens late                           -> normal: up to 3 min. Use the website (10 s) or Telegram /open (15 s).
   Message limit warning                     -> free plan ~100,000/month; the board uses about 5 per 3 minutes (~72,000 a month).

14. n8n  (weekly + monthly reports and door watchdog; runs on the laptop)
=====================================================================================================
 INSTALL AND START: double-click  5_n8n\Start n8n.bat.
   First time: downloads n8n (5-10 min) and imports both workflows. Keep the black window open (minimise it).
   Then the browser opens http://localhost:5678 (wait 1 minute and press F5 if it shows an error).
   First time only: create the local owner account (any e-mail/password - stays on your laptop).
 ACTIVATE (once): left menu "Workflows" (Overview) > open "SARTHIK Room - weekly and monthly reports" > switch the
   toggle (Inactive -> Active; newer versions call the button "Publish") > go back > same for
   "SARTHIK Room - door watchdog".
 RUN NOW (test): open a workflow > button "Execute workflow" -> the "Send due reports" / "Check door board" box turns
   GREEN and you can click it to see the output (e.g. "sent": ["Weekly report: ..."]).
 CHECK PAST RUNS: in the workflow, tab "Executions" (or left menu "Executions"): green = success, red = error.
   Click a red one to read the error message. (We keep failed runs; successful runs are not stored to save space.)
 WHAT EACH ONE DOES:
   weekly/monthly: every hour it checks "is a weekly (7 days) or monthly report due?" and if yes asks the Sheet to
        make it (Summary tab, e-mail, Telegram). If the laptop was OFF at that time, it sends it when you next turn
        n8n on (catch-up).
   watchdog: every 10 minutes it asks the Sheet "is the door board online?" and tells you ONCE on Telegram + e-mail
        when it goes offline for >5 minutes, and once when it is back.
 LAPTOP ON/OFF BEHAVIOUR:
   Laptop ON + Start n8n.bat window open: both workflows run on schedule.
   Laptop OFF or window closed: nothing runs. Nothing is lost: on the next start the hourly job catches up the
        weekly/monthly reports (the first run happens at the next hour, or press Execute workflow to catch up now).
        The watchdog does not look back in time (it reports the current state).
   Door board offline while laptop OFF: you are NOT told (no laptop = no watchdog). The Health page of the 24/7
        website still shows "door offline".
 STOP n8n: close the black window (or press Ctrl+C in it).  RESTART: close it, then Start n8n.bat again.
 n8n is reachable only from this laptop (127.0.0.1), never from the internet. Your n8n data is in 5_n8n\n8n_data.
 ERRORS -> FIX:
   "SR_SHEET_URL / SR_SHEET_KEY missing"     -> you did not start with Start n8n.bat, or Setup step 10 not done.
   "access to env vars denied"               -> start with Start n8n.bat (it sets the permission).
   "weekly failed: wrong key"                -> Sheet's HOOK_KEY differs: run Setup again (sheet step) so both match.
   Red execution "timeout"                   -> the Sheet was slow; run it again with Execute workflow.
   Browser cannot open localhost:5678        -> wait; check the black window shows "Editor is now accessible".
   "npx is not recognised"                   -> install Node.js (chapter 3c), close and reopen.
   Port 5678 busy                            -> n8n already running in another window; close it first.

=====================================================================================================
18.1 WHAT TO BACK UP (monthly, and before any change)
   a) LAPTOP WEBSITE: plug a USB drive, double-click 2_Website_v4\Backup to USB.bat (faces, photos, database).
      The website also keeps its own 14 automatic backups in data\backups. Unplug the USB afterwards.
   b) YOUR KEYS (copy to the USB too; keep the USB private):
        tools\stage3_state.json, tools\sheet_settings_code.txt, 5_n8n\n8n.env,
        1_Door_Board_v8_2\...\secrets.h, and a piece of paper with your website password.
   c) HISTORY DATA: Google Sheet > File > Download > Microsoft Excel (.xlsx). Website > Attendance > Download CSV.
   d) n8n: the folder 5_n8n\n8n_data (optional; workflows can be re-imported).
   e) Cloud copies exist already: Firestore holds all events; the Sheet holds a second copy in Events.
   The board's saved faces live inside the board; they cannot be copied out. If the board is erased you simply
   enrol again (tap card, look at camera).
18.2 RECOVERY - "the board was replaced or erased"
   Upload the firmware again with the same secrets.h. Cloud events continue. Faces: type  list  and tap each card
   to enrol again. Cards stay registered in the code; Rozy's card: learncard rozy.
18.3 RECOVERY - "laptop died / reinstalled Windows"
   Install again (chapter 3), unzip, run 2_Website_v4\Install.bat, copy your backup "data" folder into
   2_Website_v4\data, run Turn On Autostart.bat. Run "Setup Stage 3.bat" ONLY if tools\stage3_state.json is lost:
   copy the saved one back first and Setup will skip finished steps. n8n: Start n8n.bat re-imports workflows.
18.4 RECOVERY - "forgot the website password" / "member locked out"
   Console > Authentication > Users > three dots > Reset password. If YOU (admin) are locked out and have no
   reset mail: Authentication > Users > Add user (new e-mail), then Firestore > members > add that e-mail with
   role admin, name, and sign in with it.
18.5 UNDO EVERYTHING (go back to the old working version)
   Keep your earlier SARTHIK_Room_v4_Complete.zip. Upload 1_Door_Board_v8_1 to the board. That is the
   version you tested before; the cloud simply stops receiving data. Nothing else needs to change.
   Or stay on v8.2 and switch the cloud off: empty the 9 cloud lines in secrets.h and upload.
18.6 RECOVERY - "Google Sheet script stopped / deleted"
   Make a new Sheet, repeat guide step 9 (Code.gs, deploy, settings code from tools\sheet_settings_code.txt,
   menu 2). Paste the NEW web app URL into n8n.env (SR_SHEET_URL=...) and into the laptop website's
   Control > Integrations > Webhook (add  ?key=  and the same HOOK_KEY as before - it is in the settings code).
18.7 RECOVERY - "Firebase project deleted by mistake"
   Create a new project, delete  "firebase", "deploy", "accounts", "thingspeak" ... lines from
   tools\stage3_state.json "done" list (or delete the file) and run Setup Stage 3 again. History in the Sheet stays.
18.8 BEFORE CHANGING WI-FI OR KEYS: copy secrets.h to secrets_backup.h (outside the sketch folder) first.

21. SAFETY AND PRIVACY RULES
=====================================================================================================
 - Never share: secrets.h, tools\stage3_state.json, sheet_settings_code.txt, n8n.env, bot token, WhatsApp token,
   Blynk token, ThingSpeak write keys, passwords. If one leaks: create a new one in that service, then run
   Setup again for that step and upload the board again.
 - After setup untick "Enable create (sign-up)" in Firebase Authentication.
 - Only add family members you trust; viewers cannot control the door, admins can.
 - Photos and face data stay on your laptop / board. They are never uploaded to the cloud.
 - The Health page's security self-check should always show "blocked". Run it after any change to the rules.
 - The board talks to cloud services without checking certificates (usual on ESP32); access still needs its own login.
 - Do not publish your website link, your bot name or screenshots with keys on social media.
 - If the door is ever opened wrongly: Security page + Sheet Events tab + board  events  show who/when.
